Get in touch

Rabta is built and maintained by one person, so everything below reaches the same place. What differs is how quickly it gets read and what shape it needs to be in.

Sammy Almuflahi · maintainer

On this page

  1. Something is broken
  2. You want something added
  3. Something security-sensitive
  4. Elsewhere

Something is broken

Open an issue. The three things that make a report actionable are your macOS version, which connectors were running, and what you expected instead of what happened.

If a restore did something surprising, the Activity view records what each connector was asked to do and how it answered. That log is local to your machine — nothing is sent anywhere — so pasting the relevant part into the issue is usually the fastest route to a fix.

You want something added

Also an issue, and worth checking the roadmap first — some things are deliberately not planned, and that page explains why rather than leaving you guessing.

The most useful feature requests describe the situation you were in, not the feature you designed. Those get argued with productively.

Something security-sensitive

Please do not open a public issue for it. Use GitHub's private vulnerability reporting, which goes to the maintainer without disclosing anything publicly.

Rabta's whole claim is that nothing leaves your machine. If you find a case where that is not true, that is the most valuable message this project can receive, and it will be treated that way.

Elsewhere

The source, the releases and the issue tracker all live on GitHub. That is the canonical home; anything else is a mirror of what is there.

Response times are a person's, not a company's. Security reports come first; everything else gets read in order.
