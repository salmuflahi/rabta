# Rabta native toolkit: full reference scope

Owner instruction, 2026-09-09: combine the Vorssaint feature set with Rabta, improve it, and add useful capabilities. The earlier fifteen browser utilities are a starting implementation, **not fulfillment of this request**. This document supersedes the narrower priority list in rabta-suite.md.

Reference snapshot: [vorssaint/vorssaint-utils](https://github.com/vorssaint/vorssaint-utils/tree/52dbc100a44399c4ad6b980532ae5016457c0078), reviewed 2026-09-09. Its FeatureCatalog declares **57 top-level native features**. The rows below are independently written acceptance descriptions, not imported implementation source. README subfeatures remain in scope even when grouped into one row.

## Integration decision

**Selected for the current changes: independently implement equivalent capabilities.** The native toolkit, window controls and tool integrations authored in this update follow this path. No Vorssaint/GPL implementation source was imported, and Rabta's license was not changed. Source reuse remains a separate future decision, not a prerequisite for shipping these independently authored changes.

The alternatives remain documented for future scope decisions:

| Path                                                        | Consequence                                                                                                                                                                                                                                                                                                                                                                                              |

Do not assume putting the engine in a helper avoids GPL obligations. Requires the owner's licensing decision before importing and distributing it. |

The upstream [LICENSE](https://github.com/vorssaint/vorssaint-utils/blob/main/LICENSE) permits charging for copies and support, and sets requirements for modified/combined distributions and corresponding source. A subscription is not itself incompatible with GPL. Separate cloud services require their own architectural/license assessment; do not promise that every part of a tightly integrated system can remain closed.

Accounts, commercial packaging and optional hosted services remain separate product decisions. The current implementation does not depend on importing the reference engine.

## One app, specific ownership

The intended desktop experience has one Rabta shell, one command search, one menu-bar/Companion entry and one settings center. Users choose the modules they need. A separate Vorssaint app launched beside Rabta is not the requested integration.

The current Rust hub and SQLite database own workspace capture, restore and connector pairing. Rust Tauri handlers own native request validation, clipboard memory/retention, worker lifecycle and monitor sampling. `apps/desktop/src-tauri/src/native-toolkit.m` is an independently authored Objective-C bridge compiled into the app; it uses AppKit, Vision, CoreAudio, IOKit and Mach APIs for the implemented capabilities. There is no Swift service or ScreenCaptureKit recorder in this update. Window controls use an embedded, allowlisted JavaScript for Automation helper with JSON arguments, timeouts and targeted window validation. React owns the shared UI and local image/SVG/media editors. Native thumbnails, switchers and advanced recording remain unimplemented.

Each native worker or observer must have one lifecycle owner. The current clipboard service is disabled on launch, keeps text only in memory and invalidates pending reads after pause, disable or settings changes. Monitoring starts explicitly and stops polling while hidden or paused. Future native modules must preserve teardown, permission and failure boundaries; a failed utility must not take down workspace restoration. If an upstream engine is imported later, its startup/lifecycle and license requirements require a separate review.

The current native bridge is a private in-process C ABI behind named Tauri commands, not a generalized remote API. Requests use allowlisted operations and validated arguments; the generic Objective-C dispatcher is not exposed as a Tauri command. Results distinguish cancellation and failures where the operation supports them. Native exports use an explicit main-thread Save panel and atomic file writes. The bridge has no network access and receives no automatic room/AI access. A future cloud or AI action layer requires its own identity, scopes and authorization; those capabilities are not implied by this local bridge.

## Current source scope — September 9 update

- **28 desktop catalog tools:** fifteen existing utilities, nine migrated image/SVG/media tools, plus text diff, timestamp conversion, study cards/quiz and a content planner. Everyday, Developer, Creator and Student modes prioritize recommendations without hiding the full catalog. The native Mac controls are a separate panel and are not counted as 28 additional parity features.
- Image/SVG/media work runs locally in the desktop workbench and keeps originals unchanged. Native Save dialogs support cancellation and exports up to 100 MiB. Media codecs vary by Mac/runtime; unsupported tracks fail visibly. GIF image input uses its first frame, not animated GIF editing.
- The study builder derives cards from supplied notes; it does not claim AI tutoring. The content planner saves local drafts and exports timezone-resolved calendar reminders; it does not auto-post to social platforms. These additions do not convert missing native checklist rows into completed features.
- Native source now covers explicit window inventory/layouts, opt-in text history, offline screen text/barcodes, connected audio-output selection and basic live system readings. Clipboard app exclusions observe the foreground app when polling, not a guaranteed source at the instant of copying; users can pause before sensitive copies.
- See [native-toolkit-implementation.md](native-toolkit-implementation.md) and [native-windows-implementation.md](native-windows-implementation.md) for operation boundaries and remaining acceptance checks. **Objective-C/Rust compilation on a Mac, permissions, actual OS interactions and signed/notarized distribution remain release gates.** Frontend tests or a source push do not satisfy them.

## What makes the combined app better

1. Capture an image → edit in Studio → save the output with the active Workspace → reopen from Companion. Preserve the original and record derivation; no manual copying between product silos.
2. Capture a workspace's actual layout and relevant tools, then restore across supported monitors with a preview, path remapping and per-item results. Never restore into a destructive Git or file action silently.
3. Make commands context-aware: the active workspace determines recent files, capture destinations and pinned tools. One hotkey opens the same action catalog from anywhere.
4. Save chosen tool presets to the account. Local operation survives sign-out or network failure; show unsynced/conflict state clearly.
5. Give an AI a selected asset or workspace briefing with narrow read/action scopes. The AI does not receive the whole clipboard, desktop or native administrator capabilities because it is connected.

Team collaboration follows a separate product brief. Merchandise and subscription pricing remain deferred. These improvements are planned acceptance outcomes, not claims about the current release.

## Shipping gates

The current independently authored path is selected; no GPL engine import is needed for these changes. If source reuse is chosen later, pin the imported source and preserve its license, attribution and modifications record before distribution. Current native compilation and app configuration target macOS 11.0, with newer API behavior availability-gated; that target still requires a real macOS 11 run and a current-Mac run. The reference package's macOS 14 requirement does not establish Rabta compatibility. Do not change an existing download's compatibility claim before a new build is verified.

On a real Mac, verify permission granted/denied/revoked, sleep/wake, multiple displays and mixed scale, app exits/crashes, excluded apps, cancellation, memory/CPU idle budget and hotkey conflicts. Destructive, audio-capture and hardware-control modules require targeted manual checks. Build/sign/notarize Rabta itself and test one-app installation/update/removal. A Linux build or passing browser tests cannot satisfy these gates.
